# 第 1 章：The Mom Test

**原文位置**：OCR 第 102—385 行。这里的行号仅用于定位用户提供的 OCR 文本，不是纸书页码。本章先用“向妈妈推销 iPad 食谱应用”的失败对话，接着展示不透露方案、追问她实际使用行为的对话，再逐一比较好问题与坏问题。

## 应当学到什么

研究者不能把“喜欢这个想法吗”当作需求证据。善意的人会赞美你；在抽象问题上，人也会乐观高估未来行动。即使受访者没有故意说谎，这些回答仍可能误导决策。本章的三条规则是：谈对方的生活，而非自己的点子；问过去发生的具体事实，而非未来的泛泛判断；少说、多听。作者称它为 Mom Test，因为连想支持你的妈妈，也能在这样的提问下提供有用事实。

## 两段食谱应用对话

失败版先暴露“我想做一款 iPad 食谱应用”，再问妈妈会不会用、是否愿意付费。妈妈为了支持孩子，谈起自己喜欢食谱、看见应用似乎也会买。对话得到的是鼓励，无法证明她有迫切需求、愿意改变习惯或会付钱。

通过版把注意力放在她现有行为：最近怎样用 iPad、怎么发现新应用、何时购买食谱、买过的书有没有实际打开。对话揭露几个不同的商业问题：她发现应用可能依赖报纸等既有渠道；许多漂亮的食谱书是礼物却没有使用；她反而愿意买贴合特定饮食需求的书。研究者据此形成不同细分人群和获取渠道的假设。**这些仍只是线索**，不能从一次家庭对话推出市场规模或产品必胜。

## 好问题与坏问题：判断依据

| 看似有用的问法 | 缺陷 | 改成可观察的事实 |
| --- | --- | --- |
| “你觉得我的想法怎么样？” | 对方容易给礼貌性观点；把研究变成求赞美。 | “上次遇到这件事是什么时候？当时怎么处理？” |
| “你会买 X 吗？”“愿付多少钱？” | 未来承诺与价格数字看似精确，却没有真实约束。 | 查当前替代方案、实际支出、时间损失、已经分配的预算；产品成熟后可提出真实预订或付款。 |
| “理想产品有什么功能？” | 功能清单不能直接等于设计规格。 | 追问为何想要该功能、最终目标、现有流程的限制。 |
| “这件事有多烦？” | 情绪激烈不等于经济损失或购买动机。 | “它造成什么后果？”“你为处理它实际投入了什么？” |

作者赞成的问题包括“为什么还要这样做”“上次发生时请带我走一遍”“还试过什么办法”“现在怎么处理”“钱从哪个预算出”“还该找谁聊”“还有什么是我没问到的”。它们各有用途：发现目标、还原工作流、衡量代价、判断主动寻找替代方案的程度，以及在 B2B 情境中识别预算和决策链。

例如，金融人员抱怨表格往来邮件，最初要求更好的消息工具。追问他们为什么费力发送邮件，才发现根本目标是确认每个人都在用最新版文件。作者借此说明：**客户能讲清问题和约束，解决方案仍须由产品团队设计与验证**。另一位受访者声称愿意付钱解决某问题，但连搜索现成办法都没做；作者将“未主动寻找办法”视为弱需求信号。另一个人称流程是“灾难”，实际只需增加实习生处理且运行尚可；强烈用词不能代替后果评估。

## 可执行访谈步骤（本技能整理）

1. 写下一个待验证的假设，例如“这个团队每周因版本混乱浪费多少时间”，不要先展示产品。
2. 请对方还原最近一次真实事件：触发点、参与者、工具、动作顺序、耗时、费用、失败和善后。能看现场操作时，优先观察。
3. 查证既有替代方案与投入：试过什么、为什么停用、现在支付什么成本、是否主动寻找新办法。
4. 追问后果和购买流程：谁承担损失，谁掌握预算，谁能阻止购买；不要把使用者自动当付款人。
5. 在会面结束前问“还应与谁谈”“我漏问了什么”。记录原话和可核实行为，分开写自己的解释。
6. 访谈后自行提出解决方案，再用真实承诺与推进来验证；本书第 5 章专门讨论承诺与进展。

## 边界与练习

“用户说会买”最多是待验证的意向；“已经付款或付订金”是更强证据，但仍不自动证明持续使用或规模化需求。已有购买和搜索行为是重要信号，也须结合场景解释。请把你计划问客户的五个问题改写为对最近一次事件、现有花费或实际工作流的提问，并注明每题要验证的假设。若要引用作者的具体措辞或例子的数额，回查上述原文行号。
